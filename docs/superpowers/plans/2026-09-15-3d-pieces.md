# 3D Pieces Campaign Plan

> **For agentic workers:** each piece section below is executed by one piece agent, milestone by milestone. The controller reviews at every milestone marked **Gate**. Read "Shared brief" in full, then only your own piece section.

**Goal:** Eight gallery pieces from `art/ml-art-3d.md`, each a measured 3D phenomenon, rendered in several styles, verified per spec §11, and written up like the existing pieces.

**Architecture:** One directory per piece; compute scripts write raw arrays to `cache/`; render scripts read only `cache/` and draw with the shared renderer `art/_shared/r3d/`; GPU work goes through the serial queue `art/_shared/gpu1.sh`.

**Tech Stack:** `art/.venv` Python 3.12, torch 2.14+cu130, numpy/scipy, matplotlib (colormaps and 2D plates only), `r3d`, scikit-image, ffmpeg.

**Spec:** `art/ml-art-3d.md` (the piece's section, plus §0 and §9–§14)

**Why milestone granularity, not code-level steps:** these pieces are experiments whose code depends on what the data shows (toy runs decide axes, levels, cameras). Code-level steps written in advance would be guesses. Each milestone has an exact deliverable and acceptance checks instead.

## Global Constraints

- Every visual decision is a faithful rendering of a measured or exactly computed quantity or an explicit, declared aesthetic choice (spec §0).
- No height maps of planes; declare every chart; light is not data; every exterior hero ships with a cutaway or slice plate; categorical or fractal data render at voxel resolution; transfer functions are declared; slices must reproduce existing plates where they overlap (spec §0.1–0.7).
- Python: `/home/fzeng/ml/research/art/.venv/bin/python`. Never use the repo-root `.venv`; never edit `pyproject.toml`. Install packages only via `flock /home/fzeng/ml/research/art/_shared/.pip.lock uv pip install --python /home/fzeng/ml/research/art/.venv/bin/python <pkg>`, and name them in the report.
- GPU: all GPU use, including smoke tests, runs as `setsid nohup /home/fzeng/ml/research/art/_shared/gpu1.sh <cmd...> > <piece>/logs/<name>.log 2>&1 < /dev/null &`; never `art/_shared/gpu_run.sh`. gpu1 defaults to share mode (user-approved 2026-09-15): one art GPU job at a time (others queue), a start-time wait for ≥ 30 GB `MemAvailable`, and `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`; it does not wait for `autonomous/`, so art jobs may run alongside an autonomous/ GPU job. Budget memory against that concurrent job, not the whole ~120 GB pool. Use `GPU1_EXCLUSIVE=1` (also takes the autonomous/ lock and waits for no other GPU process) for timing work. Nested gpu1.sh calls inside a gpu1 job run directly. Jobs checkpoint per chunk so a rerun resumes. Call `torch.cuda.empty_cache()` between differently shaped sweeps. Expect queue waits and do CPU work meanwhile.
- CPU: `OMP_NUM_THREADS=4`, at most 4 worker processes.
- Git: `main` is shared with other agents. Commit only with `/home/fzeng/ml/research/art/_shared/commit.sh <dir> "<msg>"` (`hardware/crystal` for §3). Never `git add -A`, stash, reset, checkout, or touch another directory. Files > 20 MB are skipped by `commit.sh`; mention them in the README.
- Layout: `<dir>/README.md`, `<dir>/NOTES.md` (running log + resume commands), `<dir>/*.py` (compute separate from render), `<dir>/cache/` (gitignored, < 5 GB), `<dir>/logs/`, `<dir>/gallery/` (PNG never JPEG, MP4 + GIF, STL, SVG).
- Record the software stack in hardware captions: GB10, driver 580.173.02, CUDA 13.0, torch 2.14.0+cu130, dtype, date.
- Fractal or dimension claims need spec §11: 3D box counting over ≥ 2 decades, random oblique slices, resolution doubling, and a null through the identical pipeline.
- The user especially loves fractal, self-similar, intricate structure and the Sohl-Dickstein Spectral split; use it wherever a quantity is two-sided, and declare it.

## §5 Invariant Tori — `art/invariant-tori/`

**Sources:** `art/game-chaos/` (`replicator_c.py`, `compute_poincare.py`, `gamelib.py`, `cache/traj.npz`, README §"What was computed" and item 8).

### M1 — chart and orbits (CPU only)
- `chart.py`:
  - logits → zero-mean coordinates u ∈ ℝ⁴, two per player, via an orthonormal basis of the zero-sum plane;
  - radial map to S³: q = u/‖u‖;
  - stereographic projection from a unit pole p to ℝ³ (coordinates in an orthonormal basis of p⊥);
  - the inverse: stereographic → q → bisection on H(t q) = h → u → strategies.
- `test_chart.py`:
  - H(t u) strictly increasing in t along 10⁴ random rays at h = 2.8 (the convexity guarantee, checked numerically);
  - inverse-chart round trip < 1e-9 in strategies on 10⁴ orbit points;
  - H drift along stored orbits < 1e-8.
- Orbits (float64, reuse the C integrator):
  - ε = 0, H = 2.8: 12 orbits whose section points span the regular core from centre to edge;
  - ε = 0.5, H = 2.8: one chaotic orbit to T ≥ 2·10⁵, and 8 regular orbits with finite-time λ ≤ 5·10⁻³;
  - an ε-sweep of 26 values in [0, 0.5] with the same 12 starts.
- **Pole:** choose p to maximise the minimum angular distance to all stored orbit points; log that angle. Cache orbit points in stereographic coordinates.
- **Voxels:** the chaotic orbit's visit density on a 256³ grid over the 0.5–99.5 percentile box.
- **Poincaré section membrane:** the constraint g = x_P − x_R + y_P − y_R evaluated on a 128³ chart grid via the inverse chart. Mark points off the level set as NaN, and document how.
- **Previews** (matplotlib, three views, `cache/preview/`, not `gallery/`): nested tori at ε = 0; sea + islands at ε = 0.5.
- **Acceptance:**
  - tests pass;
  - the ε = 0 preview shows nested closed tori; if not, stop and report DONE_WITH_CONCERNS with the preview paths;
  - the report lists the pole angle, H drift and λ values.

### M2 — renders (needs r3d)
- **Nested tori:** 12 orbits as `splat_spheres` tubes coloured by torus index, in plaster, dark-glow and plotter SVG styles.
- **Sea and islands:** fog from the density volume with a declared transfer function, regular orbits as copper tubes composited using `render_volume(depth=...)`, the section membrane as a translucent iso or volume sheet, and a clip-plane cutaway.
- **Stereo:** a cross-eye pair and a red–cyan anaglyph of the sea and islands.
- **Slice plate:** the existing Poincaré plate alongside the membrane view, so the viewer sees they are one object.

### M3 — film, object, README
- **Film:** the ε-sweep, same camera, 26 keyframes with ≥ 4 interpolated frames each. Interpolation is a declared tween of camera and opacity only; orbits are never interpolated.
- **Turntable:** 360° of the sea and islands.
- **STL:** one regular ε = 0.5 orbit as a `tube_mesh` winding its torus (declared: "a torus woven from its own orbit"), watertight, scaled to 80 mm.
- **README**, including a second-pole plate (spec §5 pitfall); commit.

## §8 Combed — `art/combed/`

### M1 — flows and memorisation numbers
- **Data:** a trefoil knot x(s) = (sin s + 2 sin 2s, cos s − 2 cos 2s, −sin 3s)/3. Sample N ∈ {16, 64, 256, 1024, 4096} points with seed 0, nested (smaller sets are prefixes of the largest).
- **Path:** linear, x_t = (1 − t) x₀ + t x₁ with x₀ ~ N(0, I).
- **Closed-form field:** v*(x, t) = Σᵢ wᵢ (x₁ᵢ − x)/(1 − t), with wᵢ ∝ exp(−‖x − t x₁ᵢ‖² / (2(1 − t)²)).
  - Check it against Bertrand et al. (arXiv:2506.03719) and log the exact form used.
  - Unit test: a finite-difference check that v* transports the Gaussian mixture density (continuity equation) at 20 random (x, t) to 1e-4 relative.
- **Trained fields:** one MLP per N (4 × 256, SiLU, time embedding), trained with the conditional flow-matching loss to a fixed step budget. Log the budget; run through `gpu1.sh`.
- **Sampling:** 20,000 noise seeds shared by all fields, RK4 with 256 steps on t ∈ [0, 1 − 10⁻³] (declared stop). Repeat with 512 steps and report the max endpoint difference.
- **Memorisation:** the nearest/second-nearest training-distance ratio criterion. Read Gu et al. (arXiv:2310.02664) for the exact threshold and log it.
- **Cache:** trajectories subsampled to 64 time points.
- **Acceptance:**
  - a table of memorised fraction against N for the closed-form and trained fields;
  - the step-doubling error;
  - trajectory previews in `cache/preview/`.

### M2 — renders (needs r3d)
- **Hair:** additive glow of 20k trajectories coloured by t, for closed-form and trained at matched N (diptych).
- **Tube hero:** 400 trajectories as tubes with endpoints as spheres.
- **Plotter SVG** of 2k trajectories.
- **Basin companion:** each noise voxel of a 128³ cube in [−2.5, 2.5]³ labelled by the training point its closed-form flow reaches (N = 16), rendered as crisp voxels with an octant cutaway. No fractal claim; report 3D box counting of the label boundary to show D ≈ 2.

### M3 — film, README
- **Film:** N sweep, same seeds and camera, the memorised fraction printed per frame.
- **README** and commit.

## §4 Ribbon — `art/ribbon/`

**Sources:** `art/edge-of-stability/` (`eos_batch.py`, `cache/main4.npz`, `cache/sweep16.npz`, README "braid" and "honesty" sections).

### M1 — Stage A from cache, decide on Stage B
- Load `main4.npz`, hero 2/η = 80. Build 3D coordinates:
  - **axis 1:** the inner product of the per-step 1024-bin sketch of θ_t − θ_ref with the sketch of u₁ at a fixed reference step, normalised;
  - **axes 2–3:** the top-2 PCs of the 21-step centred mean of the sketch trajectory, orthogonalised against axis 1.
  Declare the count-sketch as an approximate inner-product-preserving random projection.
- **Validation:** correlate sketch axis 1 with the stored exact projection series in `main4.npz`, over the windows where the reference u₁ is close to u₁(t) (Gram matrix). Report Pearson r and the flip-sign agreement rate.
- **Decision rule, logged:** if flip-sign agreement ≥ 95% and r ≥ 0.9 over the EoS phase, Stage A is the M2 source. Otherwise queue Stage B.
- **Stage B** (≤ 2 h, one queued job): rerun 2/η = 80 for 6000 steps with the source's hyperparameters. Save top-3 eigenvectors every 250 steps as a fixed bank (float32), projections of θ_t − θ₀ onto the bank at every step, and θ every 10 steps (float16 is acceptable; log it). Checkpoint every 500 steps.
- **Stage C** (queued after the Stage A/B decision): a 32³ loss grid of the MLP on its 5000 images over the three M2 axes (as unit directions in weight space; Stage B gives exact directions, Stage A only sketch directions, so Stage C requires Stage B), centred at θ at the mid-EoS reference step, span ±1.5× the trajectory extent along each axis.
- **Acceptance:** r, sign agreement, the decision and its reason, and, if run, Stage B's λ₁·η/2 trace matching `main4.npz` to ≤ 5% median.

### M2 — renders (needs r3d)
- **Strands:** even and odd steps as two `splat_spheres` tubes.
- **Chords:** each GD step as a straight chord from θ_t to θ_{t+1}, drawn with `splat_additive` so their density forms the ribbon. Declared: the ribbon is the set of real steps, not a fitted surface.
- **Colour:** measured λ₁·η/2 on a diverging map centred at 1.
- **Canyon** (if Stage C exists): translucent loss shells with an octant cutaway, the ribbon inside, and depth compositing via `render_volume(depth=...)`.
- **Styles:** dark glow, plotter SVG, stereo pair.
- **Honesty panel:** the same render using the naive moving-u₁(t) projection, beside the fixed-frame one.
